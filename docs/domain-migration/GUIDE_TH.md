# ARTYVERSE X — โดเมนหลักและการย้ายงาน

โดเมนหลัก: https://artyverse-x.vercel.app
หน้ารวมข้อมูล: https://artyverse-x.vercel.app/#/transfer
ต้นทาง/กู้คืน: https://artyverse-x-ai-assistant.vercel.app/?recovery=1#/transfer

## สำหรับผู้ใช้
1. เปิดโดเมนเก่าใน browser/profile ที่มีงาน แล้วดาวน์โหลด **ไฟล์ย้ายข้อมูล** จากหน้าตัวช่วย ไฟล์รวมงาน สื่อ ประวัติ และ draft/การตั้งค่าของแอป
2. เปิดเว็บหลัก → ย้ายพื้นที่ทำงาน → เลือกไฟล์ → ตรวจจำนวนรายการและข้อขัดแย้ง เลือกว่าจะใช้ draft ฝั่งไหน ก่อนรวมให้ดาวน์โหลด backup ปลายทางไว้
3. กด **รวมและตรวจผลการย้าย** เมื่อระบบตรวจข้อมูลจริงสำเร็จจึงกดไปต่อ การตั้งค่าจะโหลดใหม่ งานในแต่ละโปรเจกต์เลือกได้จากเมนูโปรเจกต์
4. เมื่อเช็กงานบนเว็บหลักแล้ว กลับหน้าตัวช่วยโดเมนเก่าและเลือก **เปิดเว็บหลักเสมอ** เป็นการตั้งค่าเฉพาะ browser นี้ ลิงก์เดิมจะไปเว็บหลักพร้อม hash route และ mapping ID ที่เก็บจากการนำเข้า

ข้อมูลต้นทางไม่ถูกลบ แม้ตั้งเปิดเว็บหลักเสมอแล้ว ยังเข้า `?recovery=1` เพื่อกู้คืนได้ ไม่มี HTTP redirect ที่ตัดทางเข้าข้อมูลเก่า หากเปิดเว็บด้วย browser/profile/อุปกรณ์อื่น ต้องย้ายข้อมูลจาก profile นั้นแยกกัน เราไม่ได้อ้างว่าเข้าถึงหรือย้ายข้อมูลส่วนตัวใน browser ของผู้ใช้ให้แล้วจาก API ฝั่ง Vercel

## เมื่อข้อมูลขัดกัน
- ถ้า ID/เนื้อหาเหมือนกัน ใช้รายการเดิม ไม่สร้างงานซ้ำ
- ถ้า ID เดียวแต่ข้อมูลต่างกัน นำพื้นที่ต้นทางเข้าเป็นสำเนาที่เชื่อมกันด้วย ID ใหม่ เก็บงานปลายทางเดิมไว้ ประวัติ โปรเจกต์และ asset references ที่รองรับจะเปลี่ยนตาม mapping
- draft/การตั้งค่าขัดกัน: ค่าเริ่มต้นเก็บของปลายทางและเก็บต้นทางในส่วนกู้คืน หรือเลือกใช้ต้นทางแล้วเก็บปลายทางเป็นสำเนากู้คืน ตรวจค่าได้ก่อนกดใช้
- ข้อความ/โค้ดที่ผู้ใช้เขียนไม่ถูกค้นหาแทน UUID แบบเหมา รวมถึงลิงก์ภายในข้อความที่ไม่ได้เป็น reference field โดยตรง ไฟล์ย้ายต้นฉบับยังเก็บไว้ได้
- ระบบเก็บ receipt mapping บนปลายทาง เพื่อให้ URL ของ item จากโดเมนเก่าที่ส่งต่อด้วย `from=legacy` เปิดสำเนา ID ใหม่ได้ คำสั่งส่งต่อทำงานหลังผู้ใช้ยืนยันเท่านั้น

## ขอบเขตและการกู้คืน
ไฟล์เป็น JSON ไม่เข้ารหัส เก็บเป็น backup ส่วนตัว; checksum ตรวจความครบถ้วน ไม่ใช่ลายเซ็นรับรองตัวตนแหล่งที่มา ไม่รันโค้ดจากไฟล์ และไม่ส่งข้อมูลไปบริการ AI/cloud อื่น บนเว็บ Vercel ใช้ IndexedDB/service worker; local edition ใช้ API/SQLite เดิม

ขีดจำกัด: ไฟล์ย้ายไม่เกิน100MB; browser entries ไม่เกิน2000รายการ/2500000ตัวอักษรรวมและ2000000ตัวอักษรต่อค่า; records10000/media10000/revisions100000 ตาม schema/API และ media ยังต้องผ่านชนิด/ขนาด/signature ของ backend ไม่มีการแปลงข้อมูลไม่รองรับให้ดูเหมือนสำเร็จ

ก่อนรวมมีการสำรองและตรวจว่า destination ไม่เปลี่ยนหลัง review จองพื้นที่ draft ก่อนเขียน records; backend restore ใช้ transaction เดิม ส่วน IndexedDB และ localStorage ไม่ใช่ transaction เดียว หากเขียน draft ไม่ครบ จะรายงาน pending และไม่แสดงสำเร็จ เก็บไฟล์ต้นทางและ backup ปลายทางเพื่อตรวจ/ทำซ้ำ ไม่ล้างข้อมูลต้นทางเพื่อแก้ error
