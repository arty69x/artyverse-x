## Working journeys
#/home or Templates → Pattern Library → search/filter → choose an original layout → edit a browser-local draft → user-triggered opaque iframe preview → download self-contained HTML / preset or create a real CodeDocument → existing Code Studio → save/reopen through Library. Every Use action creates a new record, never silently overwrites saved work. Viewing/searching does not create user records. All8 generated layouts are original editable samples with six semantic palettes; the source catalog is explicitly Reference only.

Preset import: ≤64KB JSON → strict schema → review/cancel → apply local draft → result. Unknown executable keys/pattern IDs are rejected. Imported presets contain data, not executable HTML/JS. Current preview is invalidated when fields change. Invalid/incomplete drafts persist while create/export is disabled. New source is generated from known recipes with escaped user text; existing shared sandbox/CSP and CodeDocument v2 are reused.

## Data/design contracts
shared/patterns.ts: PatternConfig v1, eight stable pattern IDs, six style IDs, safe generator and artifact palettes. shared/reference-catalog.json:60 read-only source inventory entries. src/v3/PatternLibrary.tsx: native library/detail routes and review flow. The app's canonical tokens remain shared/design.ts; generated artifact palettes do not change the app or previously saved documents. Browser drafts are scoped by pattern ID; saved work uses the existing SQLite or hosted IndexedDB store. No data migration, remote account, scheduler, checkout, AI inference or plugin installation.

## Conflict/normalization ledger
- Latest ARTYVERSE palette/Thai fonts stay authoritative over V6/V7/V10 alternatives. V7-style colors were adapted for readable exported text; actual contrast checks are in unit tests, not copied source ratios.
- V7 was not valid JSON: removing markdown fences and appending two closing object braces permits syntactic extraction. Original retained; semantic nesting and source status remain unverified. Only isolated style reference data is used.
- Framer runtime snapshots are evidence of layout, not proof of reusable package/component entitlement. No Framer runtime, tracking, analytics, external modules, copyrighted stock media, source testimonials or vendor TSX were shipped.
- Source claims about installed tools, buildVerified, metrics, topology counts, agent confidence and test coverage are not project evidence. Three master files remain reference specifications, not executable project settings.
- Recovered source component names are catalogued only. Eight newly authored templates are implemented; this does not mean the60 entries or all master engines are completed.
